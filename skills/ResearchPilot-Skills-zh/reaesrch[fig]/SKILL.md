# 科研图件制作

用户负责确定图件展示内容、统计口径、表达形式和排列方式；本 Skill 负责根据目标版面完成尺寸计算、目录组织、绘图实现、三格式导出和质量检查。

本 Skill 完全独立，不属于 ResearchPilot 的任何阶段，也不调用或依赖其他 Skill。

## 访问边界

### 允许读取

为理解项目目标、数据含义、统计实现和已有命名，可读取项目内与当前图件相关的内容，包括但不限于：

- `code/` 下的源代码、配置、日志、结果文件和数据文件；
- `docs/` 及项目其他位置的相关 Markdown、LaTeX 和文本说明；
- 用户明确指定的其他数据来源。

只读取完成当前图件所需的文件，不把读取权限视为修改权限。当前对话中用户明确确认的要求优先于项目文档中的旧描述。

### 只允许写入

所有新建、修改、覆盖、缓存和临时项目文件必须位于项目根目录的 `code/fig/` 内。禁止修改 `code/fig/` 之外的任何项目文件，包括源代码、结果数据、文档、依赖清单和配置文件。

- 若 `code/fig/` 不存在，可创建它。
- 不创建备份、快照、历史副本或带时间戳的旧版本。
- 不把源数据复制到 `code/fig/`，除非用户明确要求。
- 不为绘图擅自修改依赖文件或项目环境。现有工具不足时，说明缺失项并请求用户决定。

## 必须读取的内置规范

开始规划任何图件前，完整读取：

- [默认版面尺寸](references/layout-defaults.yaml)
- [字体库](references/font-library.yaml)
- [颜色库](references/color-library.yaml)

建立图件规格时读取 [图件规格](references/figure-spec.md)；导出和检查时读取 [质量检查协议](references/qa-protocol.md)。

## 核心流程

1. 与用户确认每幅图展示什么、采用什么表达形式、统计口径是什么，以及图件如何排列。可以根据项目材料解释可用数据和已有实现，但不得替用户改变这些设计决定。
2. 只读检查相关源代码、结果数据和 Markdown 文件，定位真实数据来源、字段含义、统计实现、目标版面和输出要求。不得用模拟值、估计值或手工编造值替代真实结果。
3. 建立 `code/fig/layout-plan.yaml`，按 [图件规格](references/figure-spec.md) 记录每幅图、同行关系、数据来源、统计口径和尺寸来源。
4. 先在行级别计算版面，再确定单图尺寸。以宽度为主要约束；同一行的图必须在绘制前获得相同目标高度，同行图宽度与间距之和必须等于目标总宽度。不得通过导出后的缩放统一高度。
5. 为每幅图建立 `code/fig/<figure-id>/` 独立目录、`figure.yaml` 和独立绘图脚本。脚本必须能从声明的数据源独立重现该图。
6. 加载内置字体库和颜色库。字体必须精确使用 Arial，不允许静默回退；颜色必须来自颜色库的命名项或语义角色。任何例外都必须由用户明确同意并记录在 `figure.yaml`。
7. 使用真实数据按已确认口径绘图。不得擅自改变筛选、聚合、误差定义、坐标含义、图形类型、视觉编码或排列关系。
8. 从同一画布和同一绘图对象连续导出同名 PDF、SVG 和 PNG；PNG 默认 500 dpi。三种格式必须同步更新，不允许只更新其中一种。
9. 按 [质量检查协议](references/qa-protocol.md) 检查尺寸、字体、颜色、留白、裁切、重叠和格式一致性，并把结果写入单图目录中的 `qa-report.json`。
10. 查看最终尺寸的 PNG 预览。可以调整边距、图例位置、标签避让等制作细节；如果需要改变内容、统计口径或表达设计，暂停并请求用户确认。每次调整后重新同步导出三种格式并重新检查。

## 尺寸规则

配置优先级从高到低为：

1. 期刊或会议的明确尺寸要求；
2. 用户为当前图组明确指定的尺寸；
3. 用户为单幅图明确指定的尺寸；
4. `layout-defaults.yaml` 中的默认参考值。

默认值是版面参考，不是强制期刊标准。高度根据内容密度、纵横比和排列关系计算；同行图件必须等高。若目标总宽度为 `W`、同行间距为 `g_i`、各图宽度为 `w_i`，必须满足：

```text
sum(w_i) + sum(g_i) = W
```

所有绘图脚本直接以最终物理尺寸生成画布，使用 `inch = mm / 25.4` 换算，不做后期缩放。

## 目录约定

```text
code/fig/
├── layout-plan.yaml
├── <figure-id>/
│   ├── figure.yaml
│   ├── plot_<figure-id>.<py|R|其他用户指定语言>
│   ├── <figure-id>.pdf
│   ├── <figure-id>.svg
│   ├── <figure-id>.png
│   └── qa-report.json
└── ...
```

绘图语言服从用户要求或项目现有技术栈；没有明确要求时选择最适合现有数据与环境的工具。不得依赖 notebook 隐藏状态，正式图必须由单图目录内的独立脚本生成。

## 完成条件

只有同时满足以下条件才可报告完成：

- 用户确认的内容、统计口径、表达形式和排列方式均未被擅自改变；
- 每幅图具有独立目录、规格文件和可重复运行的绘图脚本；
- PDF、SVG 和 PNG 均存在并保持一致；
- 尺寸与同行约束通过检查；
- 字体、字号角色、颜色和例外声明通过检查；
- PNG 预览无明显裁切、重叠或失衡留白；
- 所有项目写入均位于 `code/fig/`。

完成时列出各图路径、物理尺寸、PNG 像素尺寸、数据来源、统计口径摘要和质量检查结果。

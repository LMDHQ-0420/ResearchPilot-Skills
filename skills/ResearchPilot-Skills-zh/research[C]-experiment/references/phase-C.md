# 阶段 C：实验设计

启动时读取本技能的 workflow-contract.md 和用户已确认的要求。完成条件是形成能回答 RQ、可执行且明确证据边界的 Part 3。

## C-1 上下文、资源与 baseline 精读

读取 Part 2 的假设和候选方法、已有环境与资源说明。已知设备、可用时间、预算不再询问；缺失且影响可执行性时集中补问。资源未知时列出假设和成本范围，不编造测量结果。

按当前问题选择相关 baseline 论文与核心训练/评估代码，直接开展已授权的只读调查。记录来源、版本、数据划分、预处理拟合范围、指标、搜索策略与实现差异。找不到代码时标明需复现及风险，不把未读全文描述为精读。

## C-2 领域惯例与可证伪假设

检索相关的近期研究和经典工作，归纳 benchmark、指标和实验惯例，并说明与当前 RQ 的关系。实验数量依证据覆盖与预算确定，避免凑够固定数量。

每个主要假设写明：支持条件、反对条件、无法区分的结果、所需对照与主要混杂因素。负结果、失败运行和不显著结果也必须保留。测试集只用于最终评估，不能反复参与调参或选择方法。

## C-3 数据、代码与执行可行性

核实数据与代码的来源、访问条件、许可和版本；检查规模、显存、运行时长和总运行次数。区分实测与估计。单个 baseline 不可用时说明替代与局限，继续不受影响的设计；核心数据不可得或科学问题无法检验时才阻塞相关部分。

## C-4 集中确认实验大纲

给出一份可审阅大纲：RQ/假设 → 实验 → 对照 → 主要指标 → 判定条件 → 成本与结论边界。分别列出完整证据方案与当前资源下核心执行方案，标明待补实验及其优先级。

方法、评估协议或成本超出已有授权时集中确认；已批准的大纲可直接展开，不重复确认阅读清单、每篇摘要或每个小节。

## C-5 撰写 Part 3

按 document-formats.md 的相关字段写入 Part 3，保留其他部分。每个实验写明设计理由、数据版本与划分、泄漏防范、指标实现、baseline 来源和选择依据、搜索预算、种子/重复次数、误差与统计报告方式。

必须报告有利、不利和不确定结果的解释路径。方法优于全部 baseline 不是验收条件；改用与 RQ 对应的预设指标、效应量和适用边界。

## C-6 成本与执行顺序

汇总每组实验显存、单次时长、运行数及总成本，注明估算依据与不确定性。按核心证据、扩展证据分批执行；不能把未执行的完整方案写成已验证结论。

## C-7 检查与交接

检查假设覆盖、对照公平、泄漏防范、资源可行性和可复现信息。输出 Part 3 路径、完成依据和未解决问题，按 workflow-contract.md 维护状态。有未决的重要设计选择时集中确认；用户已授权后续实现时继续，否则建议使用 /research[D]-implementation。

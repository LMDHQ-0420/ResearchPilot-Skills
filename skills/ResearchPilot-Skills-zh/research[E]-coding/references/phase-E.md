# 阶段 E：编码详细流程

## E-0 检查现有上下文

读取实现指南的有效内容、用户约束、项目环境与 Git 状态。复用已确认的设备、数据位置、运行策略和 README 位置。只补问无法从项目确定且影响执行的信息，不固定提问六项，不主动修改 Git 身份、分支或远程地址。

区分轻量验证与昂贵训练：按已有授权执行；缺少昂贵运行授权时给出命令与成本，继续完成不依赖该运行的工作。

## E-1 环境与数据

优先复用兼容的现有环境与锁文件，遵循用户指定的管理器；要求 uv 时按项目规则在获准根目录维护 .venv、.uv-python、.uv-cache、pyproject.toml、uv.lock 和 .python-version。不要为查看文件预建环境。

记录 Python、PyTorch、CUDA/驱动兼容信息及依赖版本、包索引和重建命令。requirements.txt 可以包含版本和 torch 系；若 torch 需专用索引或单独安装，在可复现环境说明中明确记录，不隐去这些依赖。不要混用管理器绕过用户要求。

复用真实数据；缺失时说明官方来源、版本、访问要求和预期体积。在授权内下载，禁止用模拟数据冒充实验数据。临时测试夹具必须明确标为测试用途。

维护现有 .gitignore，按需追加数据、权重、日志、.venv/、.uv-cache/、.uv-python/、__pycache__/ 和 *.py[cod] 等规则，不覆盖用户已有规则。按项目需要保留小型可复现结果文件。

## E-2 实现与日志

按实现指南的依赖顺序编码；对模块检查函数接口、tensor shape、数据流、loss/metric 口径、消融开关和配置行为。无需固定为一种目录布局，也不强制为非交互任务创建 notebook。

每个有意义的改动单元追加 dev_log.md 历史条目：原因、涉及文件、文档同步、验证命令、结果及待办。历史条目不覆盖；进度表、已知问题与当前运行说明可更新。README 仅在运行、依赖或结构变化时同步。

## E-3 实现错误与设计变化

普通 import、路径、类型或已确定语义的实现错误直接修复并验证。若实现指南存在局部错误，先修正文档再修代码并记录，无需反复请求批准。

若核心假设、方法或评估协议需要变化，给出证据、建议与受影响范围；已有授权覆盖则继续，否则集中确认一次。仅更新受影响的 Part 2、Part 3 和实现指南，不机械重做全部 B/C/D。

## E-4 必要验证

按项目与变更选择检查，优先复用现有测试。研究训练代码重点检查：

- 数据划分与预处理只在允许的训练范围拟合，测试集不参与模型选择；
- 小样本端到端冒烟运行、梯度与损失有限性；
- 指标与独立手算或可信参考结果一致；
- 关键消融开关确实改变对应计算路径；
- 配置、种子、数据版本和运行产物能关联到具体运行。

仅运行与当前变更相关的必要检查，不为措辞或日志变更新增测试。验证不足时标明“已实现/静态检查通过/冒烟通过/完整实验待运行”，不要提前标记全面验证通过。

## E-5 README、状态与可选 Git 操作

README 包含项目目标、环境重建、数据准备、训练/评估/消融命令和输出位置。按 workflow-contract.md 更新状态与完成依据。没有远程仓库或尚未完整训练，不妨碍准确报告已完成的编码范围。

只有用户授权提交/推送时才执行：先检查当前仓库、分支、远程和 diff；只暂存本次任务文件，不默认 git add .，不强制改名 main，不在已有仓库中自动初始化嵌套仓库。检查大文件和敏感配置，仅按授权目标提交与推送。

完成时列出实际运行过的检查、结果、未运行内容与风险；根据用户任务范围继续迭代或交接写作。

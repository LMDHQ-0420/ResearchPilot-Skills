# 图件质量检查协议

每次导出或调整后，对每幅图执行自动检查并查看 PNG 预览。检查结果写入该图目录的 `qa-report.json`。任何检查脚本、日志和缓存也必须位于 `code/fig/`。

## 1. 文件与可重复性

- 独立绘图脚本可以从项目根目录或图件目录以明确命令运行。
- PDF、SVG、PNG 同时存在、可打开且文件名主干一致。
- PDF 为单页图件。
- 三种格式由同一次脚本运行、同一画布和同一绘图对象生成。
- 重新运行不会在 `code/fig/` 外产生或修改项目文件。

## 2. 物理尺寸

- PDF 页面宽高与 `figure.yaml` 一致。
- SVG 的物理宽高和 `viewBox` 与目标尺寸一致。
- PNG 默认 dpi 为 500，像素尺寸满足：

```text
width_px  = round(width_mm  / 25.4 * dpi)
height_px = round(height_mm / 25.4 * dpi)
```

- 考虑格式元数据的数值舍入误差，但不得接受肉眼可见或排版显著的尺寸偏差。
- 同行图的物理高度相同。
- 同行图宽度之和加所有间距等于目标总宽度。
- 不接受导出后的缩放、拉伸或二次栅格化来修正尺寸。

## 3. 字体

- 运行前确认系统能够精确解析 Arial。
- 字体不可用或发生替代时检查失败，不静默切换字体。
- 所有文字角色均来自 `font-library.yaml`。
- legend label 与 tick label 一致。
- category label 位于 tick label 与 axis title 的字号层级之间。
- 粗体只用于字体库定义的对应角色。
- 任意字号或字体例外必须有用户明确同意，并记录在 `figure.yaml` 的 `exceptions`。

## 4. 颜色

- 图中颜色来自 `color-library.yaml` 的命名项或语义角色。
- 文本、坐标轴、刻度、背景和网格使用对应语义角色。
- 相同语义在同组图及项目现有图件中保持一致。
- categorical 色序按库中顺序使用，除非用户确认了另一语义映射。
- 连续变量不使用 categorical 彩虹色。
- 任意十六进制颜色例外必须有用户明确同意，并记录在 `exceptions`。

## 5. 数据和统计口径

- 图件读取 `figure.yaml` 声明的真实数据源。
- 筛选、分组、聚合、误差定义和随机种子与已确认口径一致。
- 核对筛选前后样本数、分组数量和关键汇总值。
- 不存在手工补值、未声明平滑、删除异常值或改变坐标范围以隐藏结果的行为。
- 数据或口径不一致属于阻断问题，不以视觉调整掩盖。

## 6. 视觉预览

以最终 500 dpi PNG 查看整体和必要的局部放大，至少检查：

- 标题、轴标题、刻度、图例、数据标签和注释是否被裁切；
- 文字之间、文字与数据、图例与数据是否重叠；
- 面板字母、轴线、刻度和基线是否对齐；
- 留白是否失衡，数据区域是否过度拥挤；
- 线、点、误差条和填充在最终尺寸下是否可辨识；
- 同行图的视觉高度、边距节奏和基线是否协调；
- 三种格式的范围、图例、文字和颜色是否一致。

允许调整边距、子图间距、图例位置、标注避让、线宽和点大小等制作细节。若修复需要改变内容、统计口径、图形类型、视觉编码或排列方式，暂停并请求用户确认。

## 7. QA 报告

`qa-report.json` 至少包含：

```json
{
  "figure_id": "fig01",
  "generated_formats": ["pdf", "svg", "png"],
  "dimensions_mm": {"width": 90, "height": 90},
  "png": {"dpi": 500, "width_px": 1772, "height_px": 1772},
  "checks": {
    "files": "pass",
    "dimensions": "pass",
    "font": "pass",
    "color": "pass",
    "data_scope": "pass",
    "visual_preview": "pass",
    "write_boundary": "pass"
  },
  "exceptions": []
}
```

无法自动验证的项目标记为 `manual-pass` 或 `blocked`，不得伪装成自动通过。只有所有阻断项解决后才能报告图件完成。
